# Какие данные нужны Zan Protect

Обучать LLM с нуля для запуска не нужно. Основной путь — готовая сильная модель + проверяемая база знаний
(RAG) + сценарии + тесты. Дообучение — отдельный эксперимент после измерения ошибок, а не условие старта.
Нормы права должны обновляться в базе, а не фиксироваться в весах модели.
Такое разделение контекста и поведения согласуется с [OpenAI о повышении точности](https://developers.openai.com/api/docs/guides/optimizing-llm-accuracy).

У пользователя пока нет материалов. Ниже рабочий список для сбора; количества — проектные ориентиры,
не обязательные требования API и не обещание качества при достижении заданного числа.

## Первая партия для закрытого пилота

| Набор | Ориентир | Обязательные поля |
|---|---|---|
| Правовые фрагменты и процедуры | 30–50 релевантных фрагментов | Текст, точный URL, название акта/органа, язык, дата проверки, действие редакции, проверяющий |
| Карточки схем | 30–60 для пилота; 150–300 для расширенного покрытия | Механизм, признаки, риск, безопасные действия, источник, RU/KK-варианты |
| Обезличенные ситуации | 100–200 разнообразных случаев, если законно доступны | Сообщение/обстоятельства, язык, ситуация, риск, объяснение, рекомендуемые действия, подтверждение эксперта |
| Документы | 7 видов × RU/KK = 14 шаблонов | Адресат, обязательные поля, допустимые просьбы, приложения, проверка юриста и переводчика |
| Независимые тесты | 120–200 сценариев | Вход, ожидаемая ветка/риск, обязательные действия, недопустимые утверждения, источники |
| Добросовестные примеры | Не менее 30–50 в тестовом наборе | Обычные вакансии, P2P/продажи/переводы, объяснение отсутствия достаточных признаков обмана |

Варианты одного случая не распределять одновременно в обучение и тест: иначе оценка будет завышена.
Сохранять семейство схемы и метку synthetic. Не называть автоматически сгенерированные примеры реальными делами.
Достаточное качество казахского проверять носителем языка с юридической компетенцией.

## Откуда брать

1. **Әділет:** действующие RU/KK редакции УК, УПК, актов о платежах, банковской деятельности,
   микрофинансировании, кредитных бюро и персональных данных; нормы отбирать под конкретные сценарии.
   Начальные кандидаты: [УК](https://old.adilet.zan.kz/rus/docs/K1400000226),
   [платежи](https://old.adilet.zan.kz/rus/docs/Z1600000011),
   [правила Антифрод-центра](https://old.adilet.zan.kz/rus/docs/V2500036742).
2. **АРРФР:** официальные инструкции и разъяснения для финансовых потребителей, например
   [памятка о мошенническом кредите](https://www.gov.kz/memleket/entities/ardfm/press/news/details/1076892?lang=ru).
3. **Нацбанк:** материалы об антифроде и [официальные ответы](https://nationalbank.kz/ru/gb/vopros-otvet).
4. **eGov / gov.kz:** актуальные пользовательские процедуры, например
   [добровольный отказ от займов](https://www.gov.kz/services/5162?lang=ru).
5. **МВД:** предупреждения о схемах, например [противодействие киберпреступности](https://www.gov.kz/memleket/entities/mvd-astana/activities/25086).
6. **Официальные банки:** памятки по безопасности и каналы обращений. Пример:
   [Kaspi о подозрительных ссылках](https://guide.kaspi.kz/client/ru/pay/security/q15362).
   Банковская памятка подтверждает позицию банка, а не содержание уголовной нормы.
7. **Практикующий юрист:** обезличенные дела, корректные шаблоны, разбор пограничных ситуаций,
   оценка того, что бот вправе утверждать на имеющихся фактах.

Машиночитаемый список ссылок: `data/resources.json`. Это кандидаты на обработку, не автоматически
опубликованные правовые источники. Не нужно скачивать весь интернет и загружать все кодексы без отбора.
Каждый фрагмент должен отвечать на конкретный вопрос и сохранять исключения/условия применения нормы.

## Как передавать материалы

- Законы и разъяснения: оригинальный текст/HTML/PDF + URL и дата. Не только скриншот без происхождения.
- Дела: JSON/JSONL или таблица с полями case_id, family_id, language, facts, risk, reasoning_summary,
  actions, source_ids, reviewer, synthetic, permission_basis. Имена, ИИН, контакты, реквизиты, подписи удаляются.
- Документы: пустые DOCX-шаблоны RU/KK и список полей. Не заполненные документы реальных заявителей.
- Скриншоты для тестов: закрыть личные данные, убедиться, что они не остались в метаданных или скрытом слое.
- Отрицательные примеры: явно отметить, почему признаков недостаточно; не требовать от модели гарантии безопасности.

Схемы JSON автоматически экспортируются командой `python -m scripts.export_schemas` в `data/schemas/`.
Проверка файла: `python -m scripts.knowledge validate --kind legal --file path/to/legal.json`.
Импорт: та же команда с action `import`; все записи сначала draft. Публикация — через защищённый admin API
после проверки. Индексация опубликованных знаний: `python -m scripts.knowledge index`.

## Когда понадобятся данные для дообучения

Если после улучшения поиска/промптов остаётся измеримая проблема — например, модель постоянно ошибается
в казахской классификации или формате ответов — подготовить отдельный набор «вход → экспертный ответ».
Начать с 200–500 тщательно проверенных примеров как проектного ориентира и сравнить с исходной моделью.
Эталонный ответ содержит факты, краткое объяснение, допустимые действия и источники; скрытые рассуждения не нужны.
Нужен отдельный holdout, не использовавшийся при подборе промптов/обучении. Применимость fine-tuning
к выбранной модели и формат API проверяются перед экспериментом. Без улучшения на holdout эксперимент не выпускать.
Практики разделения обучающих и тестовых данных: [OpenAI Fine-tuning best practices](https://developers.openai.com/api/docs/guides/fine-tuning-best-practices).

**Не нужны:** базы украденных данных, реальные пароли/SMS-коды, массовые выгрузки клиентских документов,
чужие переписки без основания на использование. Задача — научить систему распознавать механизмы и опираться
на действующие источники, а не запоминать личности пострадавших.

## Что требуется от владельца для реального запуска

Telegram-токен, LLM API-ключ и доступная модель, Railway-проект/БД, контакт юриста, лицо для редакционной
проверки материалов и решения о размещении/передаче данных. Секреты — только в Variables/.env, не в чате.
Сбор открытых источников и техническое наполнение можно выполнять без собственных реальных дел;
юридическую проверку и независимую оценку качества нельзя заменить пометкой «проверено ИИ».
