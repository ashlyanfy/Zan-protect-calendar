# ZanProtect Календарь

Командный календарь судебных заседаний и юридических событий. PWA (устанавливается на телефон), React + TypeScript + FastAPI + PostgreSQL.

**Прод:** https://app-production-b1ee.up.railway.app (Railway, проект `zanprotect-calendar`)

## Аккаунты и роли

- Вход по логину и паролю (JWT, пароли хранятся как PBKDF2-хэши).
- **Каждый сотрудник** меняет своё имя, логин и пароль сам — кнопка «Мой аккаунт» в шапке.
  Нужно подтвердить текущий пароль; после сохранения вход выполняется по новым данным.
- **Админ** (Шехерезада):
  - создаёт и удаляет аккаунты сотрудников;
  - меняет любому сотруднику имя, логин и пароль (кнопка с ключом в списке сотрудников) —
    текущий пароль сотрудника при этом не требуется;
  - открывает календарь любого сотрудника в том же виде, в каком его видит сам сотрудник
    (личные события + общие), и может создавать, редактировать и удалять в нём события;
  - редактирует любые события команды.
- **Сотрудник**: свои события + общие события команды. Чужие личные календари недоступны (403).
- События бывают **личные** (видит только автор и админ) и **общие** (видят все, редактирует автор или админ).
- Логины и пароли команды — в `backend/seed_users.json` (файл в .gitignore, в репозиторий не попадает).
  На проде аккаунты созданы через переменную окружения `SEED_USERS`. Сид отрабатывает только на пустой
  базе — логины и пароли, изменённые в интерфейсе, при перезапуске не восстанавливаются к исходным.
  Новых сотрудников заводит админ через интерфейс.

## Дизайн

Оформление повторяет стиль сайта zanprotect.kz: тёмно-синяя шапка, белое рабочее поле,
прямые углы, тонкие линии-разделители, заглавные подписи с разрядкой. Без эмодзи —
только линейные иконки (`frontend/src/components/Icons.tsx`).

## Локальный запуск

**Бэкенд** (порт 8000, локально использует SQLite `backend/zanprotect.db`):

```bash
cd backend
.venv/Scripts/uvicorn app.main:app --reload --port 8000
```

**Фронтенд** (порт 5173, проксирует `/api` на бэкенд):

```bash
cd frontend
npm run dev
```

Открыть: http://localhost:5173

## Деплой на Railway

1. Запушить репозиторий на GitHub и создать проект в Railway из этого репо — `Dockerfile` и `railway.json` подхватятся автоматически.
2. Добавить в проект плагин **PostgreSQL** — Railway сам передаст `DATABASE_URL` сервису (если нет, добавить переменную `DATABASE_URL = ${{Postgres.DATABASE_URL}}`).
3. Открыть выданный домен — фронтенд и API работают с одного сервиса.

Переменные окружения:

| Переменная | Описание |
| --- | --- |
| `DATABASE_URL` | PostgreSQL URL (задана ссылкой `${{Postgres.DATABASE_URL}}`). Без неё — SQLite для локальной разработки |
| `SECRET_KEY` | Подпись JWT-токенов (на проде задана случайная строка) |
| `SEED_USERS` | JSON-массив аккаунтов для первичного создания (см. формат `backend/seed_users.json`) |
| `ADMIN_LOGIN` / `ADMIN_PASSWORD` / `ADMIN_NAME` | Запасной админ, создаётся только если ни одного админа нет |
| `CORS_ORIGINS` | Список разрешённых origin через запятую (нужно только если фронт хостится отдельно) |

## Структура

- `backend/` — FastAPI, SQLAlchemy 2.0, Pydantic v2. CRUD `/api/events` (параметр `user_id` — календарь
  сотрудника, только для админа), `/api/auth/credentials` — смена своих данных, `/api/users/{id}` —
  управление аккаунтом сотрудника, healthcheck `/api/health`
- `frontend/` — Vite + React + TS, PWA (vite-plugin-pwa), режимы День/Неделя/Месяц, напоминания через браузерные уведомления
- `Dockerfile` — multi-stage сборка: фронтенд собирается и раздаётся FastAPI со того же домена
