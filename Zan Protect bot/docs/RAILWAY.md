# Деплой на Railway

**Обновление 0.2:** обязательна переменная `DATA_ENCRYPTION_KEY` (Fernet), для редактора — отдельная
`ADMIN_SECRET`. Генерация ключа: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
Сохраните ключ безопасно: его потеря делает старые сессии нечитаемыми. `SESSION_SECRET` и DATA_ENCRYPTION_KEY
должны оставаться одинаковыми между деплоями. Применяются обе миграции 001 и 002.
Добавлены `ENABLE_SEMANTIC_SEARCH=true`, `EMBEDDING_MODEL=text-embedding-3-small`, `EMBEDDING_DIMENSIONS=512`,
`VERIFY_ANSWERS=true`, `DAILY_REQUEST_LIMIT=30`, `MAX_CONCURRENT_REQUESTS=4`, `MAX_QUEUE_JOBS=200`.
Сессии и очередь теперь сохраняются зашифрованно в PostgreSQL. Leader lock защищает polling между деплоями,
когда все экземпляры используют одну БД. Старые замечания ниже о потере RAM-сессий относятся к версии 0.1.
Перед публичным запуском проверить свежую страницу `RELEASE_02.md`.

Конфигурация подготовлена 11.10.2026. Деплой в аккаунте Railway ещё не выполнен.
Существующий Dockerfile и railway.json в корне Law calendar относятся к календарю, не к боту.

## Сервисы

Минимально: `Postgres` + `zan-bot`. Опционально: `zan-api` из того же исходного кода.
Telegram-процесс напрямую вызывает сервисный слой: отдельный HTTP API для его работы не требуется.
Bot использует long polling — публичный домен и webhook ему сейчас не нужны.

## Последовательность

1. Загрузить код в ваш GitHub-репозиторий. Не добавлять `.env`, `.venv` и реальные обращения.
2. В Railway создать проект или добавить отдельные сервисы в существующий проект.
3. Добавить PostgreSQL, назвать сервис `Postgres`. Проверить persistent volume и настроить резервные копии.
4. Создать сервис `zan-bot` из GitHub-репозитория.
5. В Settings → Source задать **Root Directory**: `/Zan Protect bot`.
6. Для конфигурации сервиса выбрать **Railway Config File**: `/Zan Protect bot/railway.bot.json`.
   Путь к config задаётся от корня репозитория, отдельно от Root Directory. Если интерфейс не принимает
   ведущий `/`, выбрать этот же файл через доступный UI. Не использовать корневой `railway.json` календаря.
7. Убедиться в плане деплоя: Dockerfile=`Dockerfile`, pre-deploy=`python -m scripts.migrate`,
   start=`python -m app.bot`, HTTP healthcheck отсутствует.
8. Установить **одну реплику, один регион**, выключить Serverless/sleep для постоянно работающего polling-процесса.
9. Добавить Variables из таблицы ниже. Сохранить изменения и выполнить Deploy.
10. Проверить успешный pre-deploy и запуск polling; в Telegram открыть `/start` и пройти тестовые сценарии.

Если папка бота будет вынесена в отдельный репозиторий, Root Directory — `/`, config — `/railway.bot.json`.
Настройки monorepo: [документация Railway](https://docs.railway.com/deployments/monorepo).
Настройки команд и config: [Config as Code](https://docs.railway.com/config-as-code/reference).

## Variables для zan-bot

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}`, если сервис БД назван Postgres |
| `TELEGRAM_BOT_TOKEN` | Токен вашего бота из BotFather |
| `OPENAI_API_KEY` | Ваш API-ключ |
| `OPENAI_MODEL` | Доступная вашему API-проекту модель, проверенная на сценариях бота |
| `REASONING_EFFORT` | `medium` для `gpt-6-sol` |
| `API_SECRET` | Случайный секрет не короче 32 символов |
| `SESSION_SECRET` | Другой случайный секрет не короче 32 символов |
| `DATA_ENCRYPTION_KEY` | Постоянный ключ Fernet, сгенерированный командой выше; обязателен для бота |
| `ENABLE_WEB_SEARCH` | `false` для первого smoke-теста; затем `true` после проверки модели и политики обработки |
| `CONSULTATION_URL` | Реальная ссылка на запись/контакт юриста |
| `SESSION_TTL_SECONDS` | `1800` |

Два секрета можно сгенерировать локально: `python -c "import secrets; print(secrets.token_urlsafe(32))"`
— выполнить отдельно для каждого. Вставлять в Variables, не в исходный код.
`POSTGRES_PASSWORD` приложения из docker-compose не нужен: Railway выдаёт настройки своей БД.
Убедиться, что DATABASE_URL использует приватный адрес сервиса БД внутри проекта; не заменять его localhost.
Если БД называется иначе, выбрать её переменную через Reference Variable вместо буквального Postgres.
Механизм ссылок: [Railway Variables](https://docs.railway.com/variables).

`ENABLE_WEB_SEARCH=true` включает возможность поиска у оператора. В Telegram пользователь дополнительно
включает `/web_on`. Согласие на анализ также остаётся обязательным.

## Миграции и знания

Если контейнер завершается с `ValidationError` и полями `api_secret` / `session_secret`,
добавьте `API_SECRET` и `SESSION_SECRET` в Variables именно сервиса бота. Это независимые случайные
секреты приложения, не ключ OpenAI и не токен Telegram. Оба обязательны в текущей общей конфигурации,
даже если отдельный HTTP API не запущен. Проверьте также `DATA_ENCRYPTION_KEY` и повторите Deploy.
Существующие корректные ключи не заменяйте при каждом деплое. Код не генерирует их при запуске,
чтобы перезапуск не менял идентификаторы сессий и не терял доступ к зашифрованным данным.

`python -m scripts.migrate` выполняется перед запуском. SQL-файлы применяются по имени, с контрольной суммой,
в одной транзакции под advisory lock. API и bot не выполняют миграции одновременно. Ошибка блокирует новый deploy.
Существующие применённые SQL-файлы не редактировать — добавлять `002_...sql` и далее.
При подключении старой базы обязательно проверить её схему: CREATE IF NOT EXISTS не исправляет несовместимые таблицы.
Docker Compose из локального проекта в Railway не запускается.

`python -m scripts.seed` можно выполнить один раз в контейнере приложения через SSH/терминал Railway.
Команда добавляет только три учебные draft-карточки и не публикует их. Это не загрузка полноценной базы.
Миграции не требуют LLM-ключа и не делают платных вызовов.
Pre-deploy имеет доступ к переменным и сети, но не следует полагаться на файлы/том основного контейнера:
[Railway Pre-Deploy Command](https://docs.railway.com/deployments/pre-deploy-command).

## Опциональный FastAPI

Создать `zan-api` из того же репозитория с тем же Root Directory; config выбрать
`/Zan Protect bot/railway.api.json`. Добавить DATABASE_URL, OPENAI_API_KEY, OPENAI_MODEL, REASONING_EFFORT,
API_SECRET, SESSION_SECRET и ENABLE_WEB_SEARCH при необходимости. Токен Telegram этому процессу не нужен.

Команда `python -m scripts.serve_api` слушает `0.0.0.0` и порт из `PORT`, выдаваемого Railway.
Healthcheck — `/health`. Для внешних клиентов можно добавить домен; без внешних клиентов оставлять API приватным.
POST требует `X-API-Key`. Это служебный секрет — не встраивать его в браузерный JavaScript.
Текущий `/health` показывает, что приложение стартовало; это не непрерывная диагностика доступности LLM и БД.
Смысл Railway healthcheck: [документация](https://docs.railway.com/deployments/healthchecks).

## Эксплуатационные ограничения

- Одновременно не запускать локальную копию и Railway с одним Telegram-токеном. При старом webhook polling
  не работает: убрать webhook намеренно через Telegram API, предварительно остановив прежний обработчик.
- Во время rolling deploy возможен короткий конфликт двух polling-процессов; overlapSeconds=0 уменьшает окно,
  но не доказывает отсутствие пересечения. Для пилота допустим контролируемый stop/start с небольшим перерывом.
  Для production нужен leader lock либо webhook/очередь и дедупликация.
- Перезапуск очищает текущие сессии и может прервать ответы. База знаний сохраняется в PostgreSQL.
  Самому боту volume не нужен: файлы обращений в текущей реализации не сохраняются на диск.
- Настроить бюджет Railway и отдельные лимиты LLM-провайдера. Стоимость зависит от выбранных ресурсов и запросов;
  фиксированную цену без измерений проект не обещает.
- Docker-контейнер запускается non-root, но subprocess парсера ещё не является отдельной песочницей без сети/секретов.
- Проверить выбранный регион, условия передачи и хранения данных до приёма реальных обращений.
  Развёртывание на Railway само по себе не подтверждает выполнение требований Казахстана к персональным данным.

## Как проверить первый запуск

На синтетических данных: `/start` → согласие → проверка вакансии RU → KK → режим помощи → `/document police`.
Проверить DOCX/PPTX/PDF и скриншот, отсутствие источников, ответ при недоступной модели, `/delete`.
После добавления правовой базы проверить конкретные ссылки и даты норм; затем проверить переживание redeploy.
Production-критерии: `PRODUCTION_GAPS.md`.
